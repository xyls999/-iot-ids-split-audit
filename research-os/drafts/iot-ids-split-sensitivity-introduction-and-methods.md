# 论文初稿（受限技术报告版）

> **状态：仅可作为技术报告/论文骨架，不可用于投稿。**  
> 本文基于一个本地验证的 Kaggle 派生 N-BaIoT 镜像。它不声称使用官方 UCI 最终数据，不声称真实时间评估、数据泄漏、原创算法或可投稿结论。

## 暂定题目

**覆盖平衡条件下的 IoT 入侵检测评估切分敏感性：来自 N-BaIoT 镜像的可复现案例研究**

## 摘要（受限版）

机器学习入侵检测研究经常用随机方式把流量记录分成训练集和测试集。对于来自不同物联网设备的流量，这种做法可能让同一设备的相似记录同时出现在训练和测试中，从而得到比“新设备”场景更高的分数。本文对一个本地验证的 N-BaIoT 原始布局 Kaggle 镜像进行覆盖平衡的案例研究。为避免设备间攻击类别不一致造成混杂，实验仅保留九个镜像设备组共同拥有的六个类别，并在每个设备×类别单元中使用相同数量的记录。我们比较按设备×类别分层的随机行切分与留一设备组评估，并在两个有序行窗口和五个随机种子上重复实验。随机森林在随机切分下的 Macro-F1 相比平均留一设备组结果高出 0.0500–0.0958；幅度随类别和行窗口改变。条件化的原始特征设备探针同样显示设备可预测性随攻击类别显著变化。进一步的冻结轻量 MLP 表示实验未发现条件设备探针与留一设备性能差距之间稳定的正相关关系。因此，本文仅报告一个镜像层面的评估切分敏感性现象，不将设备可预测性解释为泄漏、因果机制或新方法。

**关键词：** 物联网入侵检测；跨设备泛化；评估协议；留一设备组；数据集审计；可复现性

# 1. 引言

## 1.1 问题背景

物联网（Internet of Things, IoT）设备包括摄像头、门铃、恒温器和智能音箱等。它们会产生网络流量；入侵检测系统（Intrusion Detection System, IDS）尝试从这些流量中判断设备是否处于正常状态或遭受攻击。

许多机器学习实验把全部记录随机分成训练集和测试集。这种评估在“未来记录与过去记录来自相同设备群”的场景中可能合理，但它不一定能回答另一个更困难的问题：**模型在从未见过的新设备上是否仍然有效？**

设备本身会带有稳定的流量特征，例如设备常访问的服务、协议组合、包间隔和通信频率。若同一设备的记录同时出现在训练集和测试集中，模型可能部分依赖这些设备特征。这并不自动意味着研究存在泄漏或模型无效；设备差异可能也包含真实、有用的安全信号。问题是，随机行切分所得分数是否能代表设备留出场景。

本研究选择 N-BaIoT 作为一个受限案例。原始 N-BaIoT 收集论文报告了九台商业 IoT 设备、良性流量和 Mirai/BASHLITE 攻击；UCI 记录其为顺序多变量数据，包含 115 个特征和多种攻击类别。原始论文还说明良性数据在每台设备内按时间顺序划分为训练、优化和测试部分。**但是，本文当前实验使用的并非已核验的官方归档，而是 Kaggle 镜像。** 因而本文不把镜像目录、行序或文件布局提升为官方设备映射或时间戳事实。

## 1.2 研究目标与边界

本文的目标不是提出新的 IDS 网络、域适配算法或设备指纹消除方法，而是回答一个更窄的评估问题：

> 在攻击类别覆盖平衡的镜像数据上，随机行切分与留一设备组评估之间是否存在稳定且可复现的性能差异？

本文回答以下研究问题：

- **RQ1：** 在每个设备组都拥有相同攻击类别的条件下，随机行评估与留一设备组（leave-one-device-out, LODO）评估的攻击分类性能差多少？
- **RQ2：** 这种差异是否依赖攻击类别或从每个 CSV 取样的有序行窗口？
- **RQ3：** 从一个轻量 IDS 的冻结隐藏表示中，在真实攻击类别条件下预测源设备组的能力，是否稳定地正向对应 LODO 性能差距？

RQ3 是可证伪的探索性问题。实验结果没有支持预期的正向关系，因此它被保留为负结果，而不是被包装为贡献。

## 1.3 当前允许的贡献表述

在当前证据下，本文最多可表述为以下三项技术报告贡献：

1. 给出一个**覆盖平衡**的随机行与 LODO 比较协议：只比较所有设备组都有的类别，避免把“某个攻击在某些设备根本不存在”误当成泛化失败。
2. 在一个本地验证的 N-BaIoT Kaggle 镜像上，报告随机行与 LODO 的 Random Forest Macro-F1 差距，并同时报告类别差异、模型大小和推理时间。
3. 报告两个重要限制性发现：差距对有序行窗口敏感；简单的条件设备表示探针不能稳定预测 LODO 差距。

本文**不**主张首次发现、不主张新方法、不主张设备指纹等于泄漏，也不主张有真实时间泛化结论。

# 2. 数据、可复现性与方法

## 2.1 数据来源与可复现性边界

实验归档为：

```text
research-os/data/raw/n-baiot-original-kaggle.zip
SHA-256: 077db76493e7a2f7a592bff9b16a95b9c4f1507750c5f071e3f09212412e4c64
```

该归档通过 ZIP 完整性测试，包含九个数字设备组、92 个 CSV 和 115 个数值特征。它被视为 N-BaIoT 原始布局的镜像，而非官方 UCI 最终分发物。数据来源与限制记录于：

- `data/n-baiot-uci-profile.md`
- `reports/nbaiot-original-preflight-report.md`
- `literature/iot-ids/n-baiot-primary-protocol-boundary-2026-09-30.md`

本文将设备编号称为“镜像设备组”。在取得官方文件—设备—时间段映射之前，不能把它们说成已验证的物理设备身份，也不能把行偏移称为真实时间。

## 2.2 类别覆盖控制

九个镜像设备组并非都包含相同攻击文件。设备组 3 和 7 缺少五种 Mirai 攻击。若直接使用全部类别，留一设备组的失败可能只是“测试类别从未在训练中出现”，而不是设备分布变化。

因此，主实验只保留九个设备组共同拥有的六类：

```text
benign
gafgyt.combo
gafgyt.junk
gafgyt.scan
gafgyt.tcp
gafgyt.udp
```

从每个“设备组×类别”单元读取相同数量的记录。主窗口每单元使用 600 行，共 9 × 6 × 600 = 32,400 行与 115 个特征。这个设计确保评估中每个类别在每个镜像设备组都存在，但不保证它代表完整数据分布。

## 2.3 评估切分

### 2.3.1 随机行基线

随机行基线将全部 32,400 行按“设备组×类别”组合分层，随机保留 25% 作为测试集。这样每个组合均同时出现在训练与测试中。该设置回答：当模型已经见过每个设备组的类似记录时，性能有多高？

### 2.3.2 留一设备组评估

对每个镜像设备组依次执行一次外层测试：

1. 用其余八个组的所有主窗口记录训练；
2. 仅在被留出的一个组上测试；
3. 对九个被留出组分别报告结果，而不是只给一个总分。

该设计回答：在主窗口与共同类别限定下，一个没有出现在训练集的镜像设备组上，模型表现如何？

### 2.3.3 有序行窗口敏感性

由于镜像没有显式时间戳，本文不做“时间切分”实验。作为较弱的敏感性检查，使用两段有序行窗口：

```text
窗口 A：每个 CSV 的第 0–599 行
窗口 B：每个 CSV 的第 2,000–2,599 行
```

所有其他设置不变。若结论只在一个窗口出现，就不应将其写成一般性数据集性质。

## 2.4 模型与指标

### 随机森林

主结果使用 Random Forest：100 棵树、最大深度 18、类别平衡权重、固定随机种子。记录以下资源信息：序列化模型字节数和每行 CPU 推理时间。它是传统轻量表格模型，并不是嵌入式真实部署证明。

### Logistic Regression

加入 Logistic Regression 作为线性基线。但其部分拟合达到 `max_iter=350` 后仍有收敛警告，因此其结果只作为探索性对照，不作为核心结论依据。

### 指标

- **Macro-F1：** 先算每一类的 F1，再对所有类别平均；它不会让样本多的类别完全主导结果。
- **每类 F1：** 用于发现某些攻击比其他攻击更容易受到切分方式影响。
- **DHG（device-holdout generalization gap）：** 随机行 Macro-F1 减去对应 LODO Macro-F1。正值表示随机切分更高；它不是因果效应。

## 2.5 条件设备诊断与负结果

### 原始特征条件设备探针

在每一个真实类别内部，训练一个设备组分类器预测镜像设备编号。这样避免“不同攻击类别本身不同”导致设备识别看起来很高。探针是描述性诊断：它只说明在特定类别下输入特征中还包含多少设备区分信息。

### 冻结 MLP 表示探针

为检验“设备信息是否解释泛化差距”，训练一个 32 隐藏单元的轻量 ReLU MLP 攻击分类器。对每个 LODO 折：

1. MLP 只在八个源设备组的 75% 记录上训练；
2. 在剩余 25% 源组记录上提取冻结隐藏表示；
3. 在每个真实攻击类别中，训练设备组探针；
4. 将该探针的平均 Macro-F1 与同一折的 DHG 比较。

三种种子得到的 Spearman 相关分别为 -0.600、-0.400 和 0.000，并不支持“设备探针越高，LODO 差距越大”的预期正关系。该结果禁止把该探针写成设备捷径或泄漏的可靠判据。

## 2.6 结果呈现原则

正式技术报告必须同时报告：

- 随机行与九个 LODO 折的完整结果；
- 每个类别的 F1；
- 两个有序行窗口；
- 随机种子范围；
- 警告和失败结果；
- 数据镜像、设备映射与时间语义的限制。

任何省略负结果、将行序称为时间、或将设备可预测性称为泄漏的写法，都与当前证据不一致。

# 3. 当前结果摘要（供后续结果章节展开）

Random Forest 在窗口 A 的随机行 Macro-F1 为 0.8834–0.8878，平均 LODO Macro-F1 为 0.7893–0.8020，对应差距 0.0832–0.0958。窗口 B 的差距缩小但仍为 0.0500–0.0535。

差距还依赖类别：在一个种子下，`gafgyt.combo` 与 `gafgyt.junk` 的随机行—平均 LODO F1 差距约为 0.17，而 `gafgyt.udp` 的差距为负。故不能只报告一个总平均数。

这些数字只支持“该镜像和协议下存在切分敏感性”的结论；它们不支持跨数据集泛化、真实时序泛化或方法优越性。
